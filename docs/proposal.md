# MoonBCH项目申报书

账号：**btlqql**；项目：MoonBCH；版本：**0.1.0**；日期：2026-10-30；团队：单人；主要语言：MoonBit；许可：Apache-2.0。

## 一、项目名称与摘要

**MoonBCH：支持有限域构造、缩短码解码与校验恢复流程的二进制BCH纠错库。**

项目提供纯MoonBit实现的原始窄义二进制BCH编码与硬判决纠错能力。输入是调用者选择的有限域阶数、纠错能力、本原多项式以及消息／接收比特；输出包括系统编码码字、恢复消息、纠正后码字和准确错误位置。核心实现有限域运算、共轭根生成多项式、伴随式、Berlekamp-Massey和Chien搜索，不将编码或解码转发给C、Python或外部服务。

在可复用库之外，项目提供MBCH v1块容器和文件CLI，将字节数据分块编码，恢复后校验CRC32，形成从文件保护到损坏恢复的完整演示流程。该容器是本项目定义的应用格式，不冒称已有设备或通信标准的线格式。

## 二、选题背景与实际使用场景

校验和只能帮助发现数据变化，不能直接恢复原内容。对于可以预留冗余位、需要抵抗一定数量随机位翻转的二进制记录，调用者需要明确编码参数、编码后的长度、可纠正的位错误数量，以及恢复失败的处理方式。

本项目围绕三个可复现任务组织实现：

1. **二进制记录的纠错组件。** 上层程序直接将消息比特交给BCH编码器，在读取时恢复消息并取得错误位置，用于记录级纠错或故障注入测试；不强制采用文件容器。
2. **离线文件块保护与恢复。** CLI把文件按固定参数编码为块，输入被按位破坏后逐块恢复，并验证最终字节内容。项目已经对自身实际源码文件完成该流程，而不只演示一个手写短比特串。
3. **算法移植与参数回归。** 开发者通过生成多项式、伴随式和独立参考向量核对不同m／t配置、完整码与缩短码，定位位序、补零、有限域或错误位置映射的实现差异。

这些是软件层已经支持的使用方式。项目没有真实闪存控制器、遥测设备或生产存储系统的部署证明，也不将数学上适用的场景表述为已经发生的用户采用。

## 三、实现范围、参数与处理链

当前支持的数学对象是**原始、窄义、二进制、硬判决、仅错误纠正的BCH码**。范围中的“完整”指该定义下的编码与解码流程，不泛指所有BCH变体。

| 参数／约定 | 当前实现 |
|---|---|
| 有限域 | GF(2^m)，m为2至12 |
| 父码长度 | n = 2^m - 1，最大4095位 |
| 纠错参数 | t为1至64，同时要求2t<n、生成后的消息容量k>0 |
| 本原多项式 | 各m提供默认值，也可显式指定并验证完整乘法周期 |
| 消息长度 | 1至k位；短于k时按前导零缩短语义处理 |
| 位序 | 消息与码字均为最高有效位在前 |
| 解码结果 | 消息、纠正后码字、按索引排序的错误位置 |

例如，m=4、t=2得到BCH(15,7)，冗余8位；m=8、t=2得到BCH(255,239)，冗余16位。k由实际生成多项式次数确定，不简单把所有参数下的冗余都写成m×t。

编码链为：**参数与本原多项式验证 → 有限域表 → 共轭根闭包 → 二进制生成多项式 → 系统编码**。

解码链为：**接收码字校验 → 伴随式 → Berlekamp-Massey错误定位多项式 → Chien根搜索 → 位翻转 → 伴随式复核 → 消息与位置输出**。

## 四、核心算法与工程处理

### 1. 有限域与本原多项式验证

`Bch::new`根据m构造指数表和对数表，支持有限域乘除运算。构造时遍历全部非零元素，检查是否提前回到已出现状态以及最终周期是否完整；不把任意最高次为m的多项式直接视为可用本原多项式。

错误m／t、不符合次数与常数项要求的多项式、非完整周期以及没有有效消息容量的配置均被拒绝。调用者能够读取码长、容量、纠错参数、冗余长度和生成多项式，便于核查实际编码配置。

### 2. 从共轭根构造生成多项式

从窄义BCH所需的连续根出发，收集Frobenius共轭闭包，再在有限域中相乘生成多项式。构造后检查系数是否落回二进制域，避免将有限域系数多项式直接当作二进制编码器使用。

系统编码先为冗余位保留空间，执行二进制多项式除法，最后保留原消息并附校验部分。调用者不必仅使用预设的一个BCH(15,7)样例。

### 3. 缩短码与输入位序

当消息只有s位且s≤k时，按父码消息前面补k-s个零位、再省略这些前导零的语义处理，返回长度s+(n-k)的码字。解码保留父码的代数关系，但不允许把被省略的位置当作可修复的实际接收位。

这一约定使短记录不必以全部k位形式暴露给调用者。长度不符、空消息、空／过短码字、超长码字和非0／1输入均有明确错误，不通过隐式截断处理。

### 4. Berlekamp-Massey与Chien搜索

接收码字先计算2t个伴随式。Berlekamp-Massey从该序列求出最小递推对应的错误定位多项式；若次数超过t，或后续根数与次数不符，则拒绝按一个有效纠错结果返回。

Chien搜索覆盖父码全部位置，将定位多项式的根映射回接收数组索引。对于缩短码，若推断错误落在省略的前导位置，同样拒绝。完成翻转后再次计算伴随式，验证纠正码字满足所检查的代数条件，并返回排序后的错误位置。

这些检查能发现多类不可恢复输入，但不能保证拒绝所有超过t个错误的情况；超过纠错半径后误纠正到另一合法码字，是本项目明确披露的数学边界。

### 5. MBCH块容器与安全的文件输出

`protect`将字节转换为比特，按k位消息分组，为最后一组补零，再依次写入完整n位码字。MBCH v1包含魔数、版本、m、t、保留字段、原始字节长度、原数据CRC32及编码数据。

`recover`检查版本、参数、精确帧长和两类补零，逐块纠错后按声明的原始长度恢复字节，最后验证CRC32。输出包含恢复数据、纠正位总数与纠正块数。

文件CLI采用排他创建目标文件，遇到已有路径拒绝覆盖；解码或校验失败时不写出“已恢复文件”。原始数据限制为64 KiB，编码数据同时限制为1,048,576位，参数和数据必须同时满足两个限额。

## 五、与相关能力的区别及独立贡献

项目没有把“新发明纠错算法”作为申报主张。BCH、有限域、Berlekamp-Massey和Chien搜索均为成熟方法；独立工作在于将其编码、缩短码位置处理、参数检查、错误反馈和公开API在MoonBit中实现，并通过不同路径的参考实现核对。

| 相关能力 | 与当前项目的区别 |
|---|---|
| 校验和／CRC | 主要用于发现变化；当前BCH核心在每码字错误数不超过t的条件下恢复内容 |
| Reed-Solomon字节符号码／擦除编码 | 编码符号与错误模型不同；本项目面向二进制位翻转，不将字节符号恢复结果等同于BCH位纠错 |
| LDPC软判决迭代 | 解码信息与算法不同；本项目输入硬比特，通过代数错误定位进行恢复 |
| 外部Python galois库 | 仅用于独立开发对照；MoonBit运行时不导入其源码，也不调用其编码器或解码器 |

项目查重和比较不构成“全生态不存在同类”的保证，也不把文件CLI或CRC包装单独算作算法深度。核心实现与开发参考、生成向量和应用容器分别归类。

## 六、完整案例与输入输出

### 案例一：短码字编码与两位纠错

选择m=4、t=2，消息为`1010101`，编码得到`101010111100101`。把首尾各翻转一位，接收串为`001010111100100`，解码恢复原消息并报告纠正2位。

```sh
moon run cmd/main --target js -- encode 4 2 1010101
moon run cmd/main --target js -- decode 4 2 001010111100100
```

### 案例二：实际源码文件的块损坏恢复

对已验证代码基线中的`bch.mbt`实际文件进行保护。文件长6428字节，采用BCH(255,239,t=2)，形成216个码字；在每个码字中翻转两位，共注入432个位错误，保留容器元数据完整。

恢复后逐字节比较与原文件一致，SHA-256为：

```text
6a92fa96decce5fa5856f768a6617530454c3e595e9c522c6a9d0e03c6e34212
```

该案例证明的是这份实际软件文件在已说明错误模型下的恢复。它不是存储硬件实验，也不证明任意文件、任意位置和任意数量的损坏均可恢复。

```sh
moon run cmd/main --target js -- protect 8 2 input.bin protected.mbch
moon run cmd/main --target js -- recover damaged.mbch recovered.bin
```

其中`damaged.mbch`由故障注入步骤生成，不声称编码命令本身会自动生成损坏文件。配套交付验证脚本负责编码、逐块注错和字节／哈希核对。

### 案例三：失败结果与输出边界

| 输入／操作 | 实际处理 |
|---|---|
| 非本原多项式或无效m／t | 拒绝构造编码器 |
| 非二进制比特、空或超长消息 | 返回输入错误 |
| 容器截断、长度或补零不符 | 拒绝恢复 |
| CRC32字段被改变 | 返回校验不匹配，不输出恢复文件 |
| 输出路径已经存在 | 拒绝覆盖 |
| 推断错误落在缩短码省略区域 | 返回不可纠正 |

## 七、正确性验证与独立参考

### 1. 穷举小规模完整错误空间

对BCH(15,7,t=2)的全部128条消息，分别验证无错误、全部15种单错误和全部105种双错误位置，共执行：

`128 × (1 + 15 + 105) = 15,488`个恢复案例。

不仅检查恢复消息，还核对双错误时返回的错误位置。该数字是一个穷举测试内部的案例数，不将其写成15,488个独立测试文件或重复累计不同后端执行次数。

### 2. 与独立galois实现核对

使用`galois 0.4.11`公开API和固定随机种子20261030生成66组参考数据，覆盖多组有限域与t配置、完整消息及缩短消息。核对内容包括编码后的精确比特串、注错后的解码消息和准确错误位置。

参考向量保存在`examples/galois-vectors.json`，对应MoonBit回归夹具可以在不安装Python的环境中运行。生成脚本是`scripts/reference_vectors.py`；外部参考库是MIT许可的开发依赖，不属于运行时转发执行。

### 3. 参数边界、容器和跨后端

其他测试覆盖全部支持m的默认多项式周期、替代本原多项式、缩短码各位置单错误、m=12／t=64与较高强度配置、CRC32已知参考值、多块恢复、损坏头和截断输入。

当前为**10项MoonBit测试**，其中包含上述批量验证。已在Windows本地JS、wasm、wasm-gc完成check／build／test，代码基线的GitHub Actions在JS、wasm、wasm-gc、native四后端通过。

独立工程从公共注册表安装`btlqql/moon_bch@0.1.0`，通过公共API构造BCH(15,7)、注入首尾错误并恢复；与另两个包共同执行3项API用例，三后端通过。注册表安装的`bch.mbt`、`frame.mbt`与本地对应文件SHA-256一致。

## 八、公开接口、安装与当前边界

主要接口包括`Bch::new`、`encode`、`decode`、`syndromes`、`generator_bits`，以及`protect`／`recover`和字节／比特转换。`Decoded`返回消息、纠正码字和错误位置；`Recovered`返回恢复字节、纠正位数和纠正块数。

```sh
moon add btlqql/moon_bch@0.1.0
moon test --target js
moon test --target wasm
moon test --target wasm-gc
```

保证纠正以每个码字不超过t个位翻转为前提，不能普遍保证检测或恢复超过该半径的输入。CRC32用于补充偶然损坏检查，有有限碰撞概率，不是密码学身份认证或防篡改证明。

当前不支持擦除位置输入、q元BCH、软判决、交织、特定NAND ECC布局或控制器驱动。MBCH v1的元数据不受BCH保护，需要保持完整；容器固定使用各m的默认多项式，不包含用户自定义多项式字段。未提供硬件部署、任意损坏恢复、大规模吞吐或生产性能保证。
